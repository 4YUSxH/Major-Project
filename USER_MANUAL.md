# Comprehensive User Manual

Welcome to the Student Help Desk! This manual clarifies the platform's overarching modules. Depending on your authorized identity role (Student, Faculty, Admin), your interface features uniquely scale.

## 1. Authentication & Registration
- **Student Registration**: Found at the standard Sign Up pathway `/register`. Domain mandates require `@student.university.edu`.
- **Staff Registration**: A specific, protected entryway located at `/register-staff`. Mandates `@university.edu` logic.
- **Verification Protocol**: Upon submitting a registration form, the application blocks login attempts until the user checks their designated inbox. Clicking the internal link natively triggers backend validation algorithms unlocking the account immediately.
- **Mandatory Profile Setup**: New users (after unlocking their email) will be securely trapped inside a Profile Configuration boundary, ensuring data completeness (e.g., Semesters, Departments) prior to fetching dashboard metrics.

## 2. Dashboard Ecosystems
- **Student View**: Features localized charts displaying *only* the student's personal log of active and closed queries, flanked by live system announcements.
- **Staff View**: Features aggregated metrics visualizing the backlog volume assigned exclusively to their matched `Department` node string.
- **Admin View**: Displays universal operational oversight parsing the entirety of university-wide pipelines.

## 3. Ticketing Pipelines
- **Creating Tickets (Students Only)**: Select "Launch Ticket". You must specify a categorized department explicitly (`Engineering, Administration, etc.`). 
- **Management (Staff/Admin)**: Once logged in, Staff navigate to the `Tickets` ledger. They interact natively within an expanded detail pane adjusting statuses (`Open -> Requires More Info -> Resolved -> Closed`).
- **Feedback Loops**: Staff can comment on threads requesting additional context. If marked "Requires More Info", a student receives immediate notification queues allowing them to append data securely. Once marked `Resolved`, a student may still forcefully natively reopen the connection if the friction persists.

## 4. Institutional Knowledge Base
- **Knowledge Deflection**: Located via `Knowledge Base`. All users can consume tutorials, FAQs, and institutional forms hosted here natively.
- **Administrative Control**: Standard students maintain Read-Only bindings. Admin/Faculty profiles acquire full editing permissions, capable of publishing, refactoring, or deleting categorical content to match university adjustments automatically.

## 5. Global Announcements
- The broadcast ledger relays persistent administrative events visually. Any system admin securely commands universal payloads informing populations regarding massive IT outages or sweeping scheduling alterations uniformly.

## 6. Profile Manipulation 
- Located natively by clicking the user avatar. Participants command autonomy correcting specific data fields (Branch, Title, display imagery).
